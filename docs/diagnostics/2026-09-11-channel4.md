## Confirmed cause: unsupported FairPlay Streaming key delivery

The real phone attempt used diagnostic mpv PID **3747**, with software `h264` and `aac` decoders. The root master playlist returned HTTP **200**. Both the inspected audio playlist and highest-bandwidth media playlist returned HTTP **200** and declared:

- `METHOD=SAMPLE-AES`
- `KEYFORMAT=com.apple.streamingkeydelivery`
- key URI scheme `skd`

These exact fields identify [Apple FairPlay Streaming](https://developer.apple.com/library/archive/technotes/tn2454/_index.html). The probe saved no key identifier, signed URL, key bytes or source media. The master listed up to 1024×576 AVC/AAC at 1,650,000 bandwidth; this is the same resolution and codec family as the failing production attempt.

The player logged **key-open-failed at 0.593 seconds**, followed by AAC band-count, band-type and input-exhaustion errors at approximately 0.793 seconds, and H.264 macroblock errors at approximately 2.349 seconds. At 10, 15, 40, 45 and 50 seconds the playback position remained zero, the player was idle, and no audio timestamp was reported. Software decoding reproduced the stall: changing the Pi hardware-decoder policy cannot resolve this missing-key path.

The root cause is now established for this attempt: the Channel 4 stream requires FairPlay Streaming key delivery, which the UxPlay/mpv receiver does not implement. FFmpeg's continued processing after key-open failure explains the misleading subsequent decoder errors. Generic AES decryption, adding `skd` to a protocol whitelist, changing buffering, or applying the separate GStreamer key-validation patch would not implement the required protected key exchange. UxPlay's [own documentation](../../README.md) explicitly excludes Apple video DRM; its existing AirPlay mirroring/audio FairPlay helper is not a FairPlay Streaming client.

This is a confirmed compatibility boundary, **not restored Channel 4 playback**. A supported playback endpoint is required for this protected stream. Channel 4's [current official App Store listing](https://apps.apple.com/gb/app/channel-4/id432494037) includes an Apple TV app; using that native app is a supported alternative to attempting this AirPlay path. Actual projector/HDMI compatibility on a different endpoint has not been tested here.
